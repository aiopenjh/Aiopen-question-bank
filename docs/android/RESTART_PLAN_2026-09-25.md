# Android 7단계 후반 재개 계획

- 기준: `origin/feature/android-app@b05d96f` (테스트 APK 빌드 번호 10)
- 현재 위치: 8단계 일정 중 7단계 초반 완료. 작은 UI·채점·PDF 버그 수정은 기준 브랜치에 반영됨.
- 이번 테스트 설치 방식: 참여자 전원 기존 앱 삭제 후 새 APK 설치. 구버전 데이터 이관·덮어 설치 검증은 이번 회차에서 제외하며 통과로 표시하지 않음.
- 작업 역할: 복잡한 코드 통합은 Claude, 변경 검토와 검증은 Codex. 원격 반영·APK 빌드는 별도 결과 확인 후 진행.

## 남은 순서

1. **Git 기준 정리:** 최신 Android 브랜치를 기준으로 삼는다. 오래된 `D:\ai bank` 작업 폴더의 미커밋 변경은 최신 버그 수정을 되돌릴 수 있으므로 먼저 분류·보존한다. 완료 브랜치는 최신 기준에 포함되는지 확인한 뒤 정리한다.
2. **학습 데이터 보존 수정 통합:** `feature/data-preservation@a8df0d2`의 목차·단원·백업 보호 코드를 최신 Android에 맞게 옮긴다. 구형 코드 전체를 덮어쓰지 않는다. Claude 구현 뒤 Codex가 diff, 전체 앱 테스트, 타입 검사를 확인한다.
3. **7단계 후반 실기기 재검증:** 빌드 번호 10의 두 번째 빈칸과 API 키 입력 가림 결과를 먼저 확인한다. 통합 수정이 들어간 다음 테스트 APK에서는 새 설치 → 문제 생성·풀이 → 강제 종료·재실행 → 백업·복원·초기화, PDF 저장과 주요 화면을 확인한다. 실패가 있으면 해당 항목만 수정하고 다시 확인한다.
4. **8단계 판단:** SQLite 개별 레코드 테이블 전환은 설계 문서 7장의 크기·속도 기준을 측정하거나 B2B 전체 배포를 시작할 때 진행한다. 이번 비공개 테스트의 완료와 동일시하지 않는다.
5. **출시 준비:** 비공개 테스트 결과가 안정되면 첫 정식 버전명을 `1.0.0`으로 정리하고, 개인정보 처리방침·배포 경로·Play 심사 자료를 별도 검토한다.
