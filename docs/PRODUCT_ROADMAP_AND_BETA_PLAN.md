# Celueste 제품 로드맵 및 Beta 1 계획

> **기준일**: 2026-09-22
>
> **현재 상태**: v2.4 Beta 후보 기능은 로컬 `main`에 통합, 배포 표기는 v2.3.4
>
> **핵심 슬로건**: 세상에 문제집이 없는 주제까지 나만의 지식 체계와 문제은행으로 만드는 학습 플랫폼

## 1. 제품 정체성

Celueste는 기존 문제를 재생하는 CBT가 아니라, 사용자가 원하는 학술·자격증·취미·실무 주제의 목차와 문제은행을 직접 만들고 축적하는 로컬 퍼스트 학습 플랫폼입니다.

- 자유 주제를 상위 개념, 원리, 응용, 추론으로 확장
- 과목·단원·문제·오답을 Web IndexedDB 또는 Native AsyncStorage에 보관
- 개인 API 키를 사용하며 키는 백업에 포함하지 않음
- 생성된 문제를 다시 풀 때는 AI 비용 없이 로컬 문제은행 사용
- 문제 내용과 교재는 사용자가 선택한 AI 요청 외에는 중앙 서버에 자동 업로드하지 않음

## 2. Beta 1 기능 상태

| 기능 | 현재 구현 | 상태 |
| --- | --- | --- |
| 선택형 랭킹 | 누적 풀이·초고난도·꾸준함 3개 분야, 상단 순환 표시와 순위 창, Worker/D1 API | `main` 통합, 운영 서버 설정 대기 |
| 객관식 | 4지선다 생성, 정답 위치 분산, 로컬 채점 | 완료 |
| 단답형 | 문항 생성·입력·AI 의미 판정(0/100)·결과 표시 | `main` 통합 |
| 서술형 | 체크리스트 2~5개와 배점 기반 AI 부분 채점 | `main` 통합 |
| 빈칸형 | 여러 빈칸, 허용 답안 정규화 비교, 부분 점수 | `main` 통합 |
| 문제 유형 무작위 | 문항별 객관식/주관식 범주/빈칸 독립 추첨, 고정 비율 없음 | `main` 통합 |
| 풀이공간 | 웹·네이티브 필기, 되돌리기, 전체 지우기, 문제 이동 초기화 | `main` 통합 |
| 자료 연동 | PDF 구간, TXT, MD, CSV, JSON, ZIP 연결 | 구현됨 |

HWP/HWPX는 지원하지 않으며 DOCX 텍스트 추출도 현재 지원 목록에 포함하지 않습니다.

## 3. Beta 전 반드시 마무리할 항목

### 3.1 주관식 채점 신뢰성

- AI 채점 실패를 실제 오답과 별도 상태로 표시
- 보존된 답안으로 사용자가 재채점할 수 있는 흐름 제공
- 여러 주관식 문항 병렬 호출의 공급자 제한과 비용 점검

### 3.2 랭킹 운영 전환

- `ranking_client.ts`의 개발용 Worker 주소를 운영 주소로 전환
- Cloudflare D1 실제 데이터베이스 바인딩과 마이그레이션 검증
- 랭킹 참여 동의, 전송 필드, 탈퇴·복구 정책 문구 확정
- 미참여 사용자의 학습 데이터가 전송되지 않는지 실제 네트워크 검사

### 3.3 데이터 안전성

- 백업 중첩 객체의 런타임 검증 강화
- 기존 v1/v2 알람과 구형 저장 데이터 복원 회귀 확인
- PDF 원본 미저장과 API 키 백업 제외를 실기기에서 재확인

### 3.4 실제 사용자 환경 검증

- 모바일 Safari·Chrome에서 입력 16px, 모달, 세로 스크롤, 풀이공간 확인
- 브라우저 새로고침과 앱 재실행 뒤 데이터 복구 확인
- 실제 브라우저 E2E 최소 시나리오 구축
- 알림 권한 거부·절전·방해금지 환경의 안내 확인

### 3.5 릴리스 정리

- `buildInfo.ts`를 Beta 버전으로 갱신
- `CHANGELOG.md`, `version.json`, Git tag의 버전 일치
- 타입 검사와 전체 도메인 테스트 통과
- `main` 푸시와 `gh-pages` 배포를 각각 승인받아 실행

## 4. 학원 Beta 측정 지표

- 주간 재방문율과 시험 제출 완료율
- 과목 생성 후 첫 시험까지 도달률
- 문제 유형별 생성 성공률과 채점 실패율
- AI 생성·주관식 채점의 사용자당 토큰 비용
- 생성 문항의 그대로 사용/수정 필요/폐기 비율
- 랭킹 참여율과 연속 학습 유지율
- 백업 생성·복원 성공률과 데이터 손실 신고 건수

가격이나 구독 모델은 실제 토큰 비용과 유지율을 확보한 뒤 결정합니다.

## 5. 브랜치와 릴리스 운영

- `main`: 현재 객관식·주관식·빈칸형·풀이공간·랭킹 클라이언트가 통합된 기준 브랜치
- `feature/*`: 별도 기능을 격리 개발하고 검증 후 `main`에 병합
- 병합 전: 변경 범위 테스트와 TypeScript 검사
- 배포 전: 운영 외부 연결, 버전, 개인정보 경계, 백업 복원을 추가 확인
- 프로덕션 배포: 사용자의 명시적 승인 후에만 `deploy-gh-pages.ps1` 실행

## 6. 권장 진행 순서

1. 주관식 채점 실패 상태와 재채점 UX 보완
2. 랭킹 Worker 운영 연결과 개인정보 고지 확정
3. 모바일·브라우저·백업 E2E 검증
4. Beta 버전 및 변경 이력 갱신
5. 제한된 인원 사전 테스트
6. 학원 전체 Beta 1 배포와 지표 수집
