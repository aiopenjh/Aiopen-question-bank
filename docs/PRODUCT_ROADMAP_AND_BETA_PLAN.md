# Celueste 제품 로드맵 및 Beta 1 계획

> **기준일**: 2026-09-25
>
> **현재 상태**: Android 테스트 코드는 `feature/android-app`에 통합되고 테스트 APK로 실기기 확인 중. 공개 웹 `main`과 별도이며 첫 정식 Play 출시·iOS 출시는 하지 않음
>
> **제품 가설**: 일반 개인이 자기 자료와 학습 주제로 문제를 만들고, 틀리거나 헷갈린 부분을 반복 연습하는 문제은행. 특정 시장의 수요가 검증됐다는 뜻은 아님

## 1. 제품 정체성

Celueste는 일반 개인이 원하는 학술·자격증·취미·실무 주제의 목차와 문제은행을 직접 만들고 축적하는 로컬 퍼스트 학습 앱입니다. 첫 고객을 학원이나 학교로 가정하지 않으며, 특정 시험 준비에 실제 도움이 되는지는 테스트로 확인해야 합니다.

- 자유 주제를 상위 개념, 원리, 응용, 추론으로 확장
- 과목·단원·문제·오답을 웹 IndexedDB 또는 Android SQLite에 보관
- 개인 API 키를 사용하며 키는 백업에 포함하지 않음
- 생성된 문제를 다시 풀 때는 AI 비용 없이 로컬 문제은행 사용
- 문제 내용과 교재는 사용자가 선택한 AI 요청 외에는 중앙 서버에 자동 업로드하지 않음

## 3. Beta 전 반드시 마무리할 항목

### 3.0 앱 등록을 위한 문제 생성 통로 결정

운영자의 AI API 키를 앱 번들에 포함하는 방식은 사용하지 않습니다. 배포된 웹·APK·앱스토어 앱에서는 키가 추출될 수 있습니다.

| 선택지 | 장점 | 확인할 사항 |
| --- | --- | --- |
| 사용자 API 키(BYOK) 유지 | 서버 비용과 운영 부담이 작고 현재 구조를 그대로 활용 | 일반 사용자의 키 발급·입력 장벽 |
| 관리형 AI 프록시 | 사용자는 키 없이 바로 사용 가능 | 로그인, 사용자별 할당량, 결제·비용 제한, 악용 방지, 개인정보 고지 필요 |
| 온디바이스 모델 | 외부 전송과 호출 비용을 줄일 가능성 | 앱 용량, 기기 성능, 문제 품질, 모델 라이선스 검증 필요 |

현재 결정은 **데모·검증은 사용자 API 키(BYOK)로 진행하고, 일반 고객 대상 정식 출시 전에는 운영자 키를 안전한 관리형 서버 프록시 뒤에 두는 것**입니다. 관리형 프록시는 아직 구현되지 않았고 인증·사용량 제한·비용 통제·악용 방지·개인정보 고지를 먼저 설계해야 합니다. 랭킹 Worker는 점수 동기화만 담당하며 AI API 키를 보관하거나 문제를 생성하지 않습니다.

### 3.1 주관식 채점 신뢰성

- AI 채점 실패를 실제 오답과 별도 상태로 표시 — Android 테스트 코드에서 완료
- 보존된 답안으로 사용자가 재채점할 수 있는 흐름 제공
- 여러 주관식 문항 병렬 호출의 공급자 제한과 비용 점검

### 3.2 랭킹 운영 전환

- 웹의 운영 Worker 연결은 유지하고 Android 테스트 빌드에서 실제 URL·탈퇴 동작 확인
- Cloudflare D1 운영 바인딩·데이터 처리 범위 재확인
- 랭킹 참여 동의, 전송 필드, 탈퇴·복구 정책 문구 확정
- 미참여 사용자의 학습 데이터가 전송되지 않는지 실제 네트워크 검사

### 3.3 데이터 안전성

- 백업 중첩 객체의 런타임 검증 강화
- 기존 v1/v2 알람과 구형 저장 데이터 복원 회귀 확인
- PDF 원본 미저장과 API 키 백업 제외를 실기기에서 재확인

### 3.4 실제 사용자 환경 검증

- 모바일 Safari·Chrome에서 입력 16px, 모달, 세로 스크롤, 풀이공간 확인
- 브라우저 새로고침과 앱 재실행 뒤 데이터 보존 확인. Android 테스트 기기에서 재실행 후 기존·새 자료 유지 확인됨
- 실제 브라우저 E2E 최소 시나리오 구축
- 알림 권한 거부·절전·방해금지 환경의 안내 확인

### 3.5 릴리스 정리

- 첫 정식 출시 때 `app.json`, `buildInfo.ts`, `version.json`의 사용자 표시 버전을 `1.0.0`으로 정리. EAS 내부 `versionCode`는 계속 증가
- `CHANGELOG.md`와 출시 태그의 버전·배포 범위 일치
- 타입 검사와 전체 도메인 테스트 통과
- `main` 푸시와 `gh-pages` 배포를 각각 승인받아 실행

## 4. 개인 사용자 Beta 측정 지표

- 주간 재방문율과 시험 제출 완료율
- 과목 생성 후 첫 시험까지 도달률
- 문제 유형별 생성 성공률과 채점 실패율
- AI 생성·주관식 채점의 사용자당 토큰 비용
- 생성 문항의 그대로 사용/수정 필요/폐기 비율
- 랭킹 참여율과 연속 학습 유지율
- 백업 생성·복원 성공률과 데이터 손실 신고 건수

가격이나 구독 모델은 실제 토큰 비용과 유지율을 확보한 뒤 결정합니다.

## 5. 브랜치와 릴리스 운영

- `main`: 공개 웹 코드의 기준 브랜치. Android 테스트의 최신 코드는 아직 병합하지 않음
- `feature/android-app`: Android 테스트 코드의 기준 브랜치
- `feature/*`: 별도 작업을 격리 개발하고 승인·검증 후 대상 브랜치에 병합
- 병합 전: 변경 범위 테스트와 TypeScript 검사
- 배포 전: 운영 외부 연결, 버전, 개인정보 경계, 백업 복원을 추가 확인
- 프로덕션 배포: 사용자의 명시적 승인 후에만 `deploy-gh-pages.ps1` 실행

## 6. 권장 진행 순서

1. Android 실기기에서 남은 문제 신고 수신 경로와 최신 APK 사용성 확인
2. Android와 `main`의 변경 차이를 검토하고 웹 회귀 후 별도 승인으로 병합
3. 제한된 개인 사용자 Beta에서 문제 품질·반복 사용·비용·백업 복원 확인
4. 관리형 AI 프록시와 개인정보 처리방침을 설계·검증
5. 정식 출시 표시 버전 `1.0.0`, 스토어 자료·지원 경로 정리 후 승인된 대상만 배포
