## 1. Golden Set으로 현재 품질 기록

첫 평가 대상은 교재 한 단원으로 좁힌다. 출제와 채점 사례를 합쳐 약 10건을 준비하고, 테스트에 사용할 자료 버전, 근거 구절, 기대 정답 또는 기대 판정을 사람이 먼저 확정한다. 실제 교재 대신 공유 가능한 자료나 검증용 예제도 사용할 수 있다.

문제은행은 같은 주제로 여러 문항을 만들 수 있다. 출제 사례에는 문항 표현을 고정하는 대신 **반드시 다룰 개념, 정답 조건, 근거 구절**을 기록한다. 채점 사례에는 같은 문항과 답안, 기대 점수 또는 체크리스트 판정을 고정한다.

| 대표 사례 | 기대 결과 |
| --- | --- |
| 필요한 공식이 텍스트 자료의 4,000자 이후에 있음 | 해당 구절이 출제 문맥에 들어가고, 문항이 공식과 적용 조건을 유지한다. |
| 교재에 정확한 용어가 나오고 출제 요청에는 동의어가 쓰임 | 같은 개념의 근거를 찾을 수 있다. |
| 계산에 공식과 예외 조건이 모두 필요함 | 두 근거를 모두 사용하며 정답과 해설의 계산이 일치한다. |
| 교재 기반 출제 요청에 필요한 근거가 없음 | 제공된 교재로 확인할 수 없음을 알린다. |
| 단답형 답안의 표현만 달라짐 | 핵심 의미가 같으면 정답으로 판정한다. |
| 서술형에서 조건 하나가 빠지거나 단위·부호가 틀림 | 사람이 정한 해당 항목의 부분 점수나 오답 판정과 일치한다. |

첫 실행 결과를 기준으로 남긴다. 이후에도 같은 자료, 출제 요청, 채점 답안과 설정을 사용한다. 모델이나 검색 설정을 바꿨다면 버전과 변경점을 함께 기록해 결과 차이의 원인을 추적한다.

## 2. 교재 근거 검색 개선

앞부분만 잘라 보내는 현재 방식과, 선택한 과목·단원과 관련된 문단을 먼저 골라 보내는 방식을 Golden Set으로 비교한다. 텍스트 교재를 문단이나 섹션으로 나누고, 각 조각에 자료 버전과 문단 위치를 붙인다. 우선 로컬에서 단원명·핵심 용어로 관련 구절을 고르는 방식부터 적용해 본다.

```text
과목·단원 선택 → 연결된 교재에서 후보 문단 검색
             → 필요한 공식·조건을 포함한 구절 선택
             → 근거를 넣어 출제 → 정답·해설과 근거 연결
```

표현이 달라 필요한 자료를 놓치는 경우가 남으면 벡터 검색이나 하이브리드 검색을 비교한다. 필요한 조각이 후보에는 있지만 상위에서 밀리는 경우에는 리랭킹을 비교한다. 이 계획의 첫 검증은 기존 로컬 퍼스트 구조에서 시작한다. 대용량 PDF 처리와 OCR은 [교재 서버 설계](textbook/LARGE_TEXTBOOK_PROCESSING_DESIGN.md)에서 다룬다.

## 3. 문항 근거와 채점 품질 검증

- **출제**에서는 문항별로 확인한 근거의 자료 버전과 위치를 연결하는 방안을 검토한다. 확인된 원문으로 정답과 해설을 뒷받침할 수 있는지 보고, 객관식은 정답이 하나로 결정되는지도 확인한다.
- **채점**에서는 사람이 판정한 고정 답안을 사용해 정답 인정 범위, 부분 점수, 오답 판정을 비교한다. 채점 요청 자체의 실패는 품질 저하 원인을 분석할 때 결과와 분리한다.
- **실패 원인**은 필요한 근거가 입력에 없었는지, 근거가 있었는데 출제·해설이 틀렸는지, 올바른 답안을 잘못 채점했는지로 나눠 기록한다.

## 검증 기준

| 구분 | 비교할 값 |
| --- | --- |
| 근거 제공 | 기대한 근거가 실제 출제 입력에 포함된 사례 수 |
| 출제 품질 | 정답과 해설이 근거에 맞고 적용 조건을 보존한 문항 수 |
| 채점 품질 | 사람의 정오·부분 점수 판정과 일치한 사례 수 |
| 처리 비용 | 출제 입력량과 응답 시간, 평가 과정에서 발생한 추가 모델 호출 수 |

현재 결과와 개선 후 결과를 같은 평가셋으로 비교해 어떤 실패가 줄었는지 확인한다. 검색 개선을 적용했다면 필요한 근거가 후보에 들어왔는지와 최종 문맥에 남았는지를 따로 본다. 세부 출시 검증은 [제품 로드맵 및 Beta 계획](PRODUCT_ROADMAP_AND_BETA_PLAN.md)에 따른다.

이 문서는 GitHub 코드 검토에 근거한 계획이다. Golden Set 제작, 검색 파이프라인 구현, 실제 AI 호출을 통한 품질 측정은 적용 단계에서 진행한다.
