# 모바일 입력창 키보드 대응 계획

의견 보내기 입력창은 먼저 개선한다. 아래 10개 입력창은 다음 작업에서 공통 키보드 대응을 적용한다.

## 남은 대상

| 화면 | 파일 | 입력창 수 | 현재 구조 |
|---|---|---:|---|
| 백업 텍스트 복원 | `BackupModal.tsx` | 1 | 중앙 모달, 내부 스크롤 없음 |
| 내 자료 업로드 | `SourceUploadModal.tsx` | 3 | 하단 모달, 내부 스크롤 있음 |
| 새 과목 등록 | `TopicModal.tsx` | 2 | 중앙 모달, 내부 스크롤 있음 |
| 새 단원 추가 | `UnitModal.tsx` | 1 | 중앙 모달, 내부 스크롤 없음 |
| 메인 새 과목 입력 | `StudyMapScreen.tsx` | 1 | 메인 화면 스크롤 내부 |
| 일일 학습 목표 | `DailyGoalSection.tsx` | 1 | 설정 화면 스크롤 내부 |
| API 키 등록·교체 | `ApiKeySection.tsx` | 1 | 설정 화면 스크롤 내부 |

## 적용 원칙

1. 웹/PWA는 `visualViewport`로 키보드가 차지한 높이를 계산한다.
2. 네이티브 iOS/Android는 `KeyboardAvoidingView`와 키보드 인셋을 사용한다.
3. 포커스된 입력창과 저장 버튼이 키보드 위에 남도록 모달 높이와 내부 스크롤을 조정한다.
4. 키보드가 열리고 닫힐 때 짧은 이동 애니메이션을 적용한다.
5. 입력창 글꼴은 모바일 자동 확대를 막기 위해 16px 이상을 유지한다.
6. 입력 중 가로 페이지 이동이 개입하지 않도록 기존 제스처 차단 규칙을 유지한다.

## 검증 기준

- Android Chrome/PWA와 iPhone Safari/PWA에서 입력창을 한 번 탭해 바로 입력할 수 있다.
- 키보드가 저장·전송 버튼을 가리지 않는다.
- 키보드를 내리면 화면이 원래 위치로 복귀한다.
- 입력 내용과 저장 동작은 기존과 동일하다.
