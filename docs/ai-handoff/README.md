# Celueste AI 인수인계함

Claude와 Codex가 긴 대화 내용을 사용자가 반복해서 복사하지 않고, 같은 저장소의 파일을 기준으로 구현과 검토를 주고받기 위한 작업 규칙입니다.

이 구조는 두 채팅을 직접 연결하지 않습니다. 각 AI가 작업을 시작할 때 인수인계함을 읽고, 자기 역할의 파일과 상태만 갱신합니다. 별도의 자동 실행기가 없는 동안에는 사용자가 다음 담당 AI에게 짧게 작업 시작을 알려야 합니다.

## 파일 역할

| 파일 | 작성 담당 | 용도 |
| --- | --- | --- |
| `TASK.md` | 작업을 처음 맡은 AI | 사용자 요청, 승인 범위, 기준 브랜치와 완료 조건 |
| `CLAUDE_REPORT.md` | Claude | 구현 커밋, 변경 파일, 검증 결과, 미해결 사항 |
| `CODEX_REVIEW.md` | Codex | 코드 검토 결과, 수정 요청, 최종 판정 |
| `STATUS.json` | 현재 담당 AI | 현재 단계, 담당자, 반복 횟수, 산출물 위치 |

## 상태 흐름

```text
idle
  -> claude_implementation
  -> codex_review
  -> claude_revision       (수정이 필요할 때만)
  -> codex_final_review    (수정 후 재검토)
  -> owner_approval
  -> complete
```

진행할 수 없는 문제가 있으면 `blocked`로 바꾸고 `TASK.md` 또는 담당 보고서에 필요한 사용자 결정을 기록합니다.

## 공통 규칙

1. 작업 시작 시 `STATUS.json`, `TASK.md`, 직전 담당자의 보고서를 먼저 읽습니다.
2. 구현 담당은 `CLAUDE_REPORT.md`만, 검토 담당은 `CODEX_REVIEW.md`만 결과 문서로 사용합니다.
3. 코드와 문서의 실제 상태가 보고서보다 우선합니다. 커밋 해시, 브랜치, 번들 또는 패치 경로를 반드시 적습니다.
4. 같은 파일을 두 AI가 동시에 수정하지 않습니다. `STATUS.json`의 `activeAgent`가 아닌 AI는 코드 변경을 시작하지 않습니다.
5. 검토는 기본적으로 읽기 전용입니다. Codex가 직접 수정하려면 사용자의 명시적인 수정 요청이 필요합니다.
6. 검토 반복은 기본 2회까지만 허용합니다. 그 이상은 사용자에게 선택지를 보고합니다.
7. `push`, `merge`, `deploy`, 데이터 삭제와 운영 환경 변경은 항상 사용자 승인을 받은 뒤 별도 단계로 수행합니다.
8. API 키, 복구 토큰, 사용자 문제 내용과 개인정보를 인수인계 문서에 기록하지 않습니다.
9. 대용량 diff를 문서에 붙이지 않고 커밋, 번들, 패치 파일 경로만 기록합니다.
10. 작업이 끝나면 `STATUS.json`을 갱신하고 다음 담당자가 읽어야 할 파일을 명시합니다.

## 역할별 절차

### Claude: 구현 담당

1. `TASK.md`의 범위와 승인 내용을 확인합니다.
2. `STATUS.json`을 `claude_implementation` 또는 `claude_revision`으로 갱신합니다.
3. 승인된 범위만 구현하고 검증합니다.
4. `CLAUDE_REPORT.md`에 커밋과 검증 결과를 기록합니다.
5. `STATUS.json`을 `codex_review`로 바꾸고 `activeAgent`를 `codex`로 넘깁니다.

### Codex: 검토 담당

1. `TASK.md`, `CLAUDE_REPORT.md`, 실제 diff를 확인합니다.
2. 테스트를 실행하라는 요청이 없으면 코드와 기존 결과만 검토합니다.
3. `CODEX_REVIEW.md`에 중요도별 발견 사항과 판정을 기록합니다.
4. 수정이 필요하면 `claude_revision`, 통과하면 `owner_approval`로 상태를 바꿉니다.
5. 사용자 승인 없이 구현 커밋을 병합하거나 푸시하지 않습니다.

## 사용자 단축 문장

- Claude에게 작업 시작: `인수인계함에 작업을 등록하고 구현해줘.`
- Codex에게 검토 요청: `Claude 작업 검토해.`
- Claude에게 수정 요청: `Codex 검토 파일을 읽고 수정해줘.`
- Codex에게 최종 확인: `수정본 최종 검토해.`

각 AI는 위 문장을 받으면 긴 대화 재전달을 요구하지 말고 이 디렉터리의 파일과 실제 Git 상태를 읽습니다.
