# Celueste 랭킹 기능 설계 문서

이 폴더는 `feature/ranking` 브랜치에서 준비 중인 선택형 공동 랭킹의 계획과 서버 계약을 기록한다. 현재 단계는 **설계 완료 전 초안**이며, 랭킹 코드나 외부 서버는 아직 만들거나 배포하지 않았다.

## 문서 구성

- [기능 계획서](./RANKING_FEATURE_PLAN.md): 목적, 사용자 흐름, 구현 단계와 완료 조건
- [API 명세](./RANKING_API_SPEC.md): 전송 데이터, 엔드포인트, 중복 방지와 복구 방식
- [서버 선택안](./RANKING_SERVER_OPTIONS.md): 운영 방식 비교와 권장안

## 현재 확정된 방향

1. 참여를 원하는 사용자만 닉네임을 등록한다.
2. 자동 수집하지 않고 사용자가 `오늘 학습 연동`을 눌렀을 때만 전송한다.
3. 서버에는 오늘 완료한 문제 수와 랭킹 식별에 필요한 최소 정보만 보낸다.
4. 문제 내용, 보기, 정답, 과목명과 개인 API 키는 보내지 않는다.
5. 랭킹은 `최다 문제 풀이 왕`과 `꾸준함 왕` 두 항목만 운영한다.
6. 하루 3문제 이상 완료하면 그날을 꾸준함 참여일로 인정한다.
7. 같은 날 여러 번 연동해도 문제 수가 중복 누적되지 않도록 그날의 최댓값으로 갱신한다.
8. 닉네임과 랭킹 복구 정보는 기존 백업에 추가하되, API 키는 계속 제외한다.

## 구현 전 결정이 필요한 항목

- 권장 서버인 Cloudflare Workers + D1 사용 승인
- 한 사용자가 두 항목 모두 1위일 때 두 칸에 중복 표시할지 여부
- 닉네임 변경 횟수 제한과 탈퇴 데이터 보관 기간

이 세 항목이 결정되기 전까지 문서 외 랭킹 구현과 외부 서비스 설정은 진행하지 않는다.
