# Celueste 랭킹 기능 설계 문서

이 폴더는 `feature/ranking` 브랜치의 선택형 공동 랭킹 계획과 서버 계약을 기록한다. 모바일 랭킹 화면과 Worker 코드는 구현되어 있으며, 현재는 **31레벨 이상 순차 도전 수정 단계**다. 실제 서버 배포 상태는 이번 작업에서 확인하지 않았다.

2026-09-22 작업 범위·검증·병합 전 확인사항은 [순차 도전 변경 기록](./SEQUENTIAL_CHALLENGE_2026-09-22.md)을 우선 참고한다.

## 문서 구성

- [기능 계획서](./RANKING_FEATURE_PLAN.md): 목적, 사용자 흐름, 구현 단계와 완료 조건
- [API 명세](./RANKING_API_SPEC.md): 전송 데이터, 엔드포인트, 중복 방지와 복구 방식
- [서버 선택안](./RANKING_SERVER_OPTIONS.md): 운영 방식 비교와 권장안

## 현재 확정된 방향

1. 참여를 원하는 사용자만 닉네임을 등록한다.
2. 자동 수집하지 않고 사용자가 `오늘 학습 연동`을 눌렀을 때만 전송한다.
3. 서버에는 오늘 완료한 문제 수, 최고 순차 통과 레벨과 랭킹 식별에 필요한 최소 정보만 보낸다.
4. 문제 내용, 보기, 정답, 과목명과 개인 API 키는 보내지 않는다.
5. 랭킹은 `최다 문제 풀이 왕`, `꾸준함 왕`, `초고난도 도전` 세 항목이다. 도전은 과목별로 31부터 순차 통과한 최고 레벨을 사용한다.
6. 하루 3문제 이상 완료하면 그날을 꾸준함 참여일로 인정한다.
7. 같은 날 여러 번 연동해도 문제 수가 중복 누적되지 않도록 그날의 최댓값으로 갱신한다.
8. 닉네임과 랭킹 복구 정보는 기존 백업에 추가하되, API 키는 계속 제외한다.

## 서버 결정 보류

- Cloudflare Workers + D1 유지 또는 Supabase 통합은 사용자가 추후 결정한다.
- 서버 운영·배포·인증·탈퇴 정책은 이번 순차 도전 수정 범위에서 제외한다.
- 같은 사용자가 여러 항목에서 1위이면 각 항목에 그대로 표시한다.

모바일 코드를 수정했다는 이유로 서버 배포나 운영 정책까지 확정한 것으로 해석하지 않는다.
